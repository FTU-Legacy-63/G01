2. **How were the game rules, startup financial information, scenarios, interface design and code integrated? Identify the members responsible for the main integration and verification activities.**

The components of Pitch & Ledger were **integrated through a modular architecture** that separates case content, game rules and interface presentation. **Case-specific files** contained startup financial information, company descriptions, dialogue scenarios, checklist benchmarks and investment terms. **Presentation files** defined each case’s artwork and display settings. **Shared core modules** handled investment constraints, checklist evaluation, capital allocation, campaign progress and report calculations. **Interface modules** then used these data and results to display the pitch, documents, founder investigation, investment decision and reports. This modular design choice allowed **minimal shared responsibilities**, which meant easy bug-fixing and update of individual cases without unnecessarily changing the shared calculation logic.

Integration also required **translating the team’s interface designs** and reference materials from Figma into HTML and CSS, and **connecting interface controls** to the appropriate game functions. For example, players can access the Decision screen directly, but confirmation remains unavailable until all checklist questions are answered, an Invest or Reject choice is made and any investment allocation is valid. Once confirmed, the decision is recorded in the campaign ledger, a case report is displayed and the player can continue. The final report consolidates the results across all three cases.

The responsibility of coordinating this integration, including consolidating the team’s materials, communicating implementation requirements, reviewing the resulting builds and organizing revisions, is attributed to Phu Minh. AI assisted with translating the supplied materials into code and implementing changes.
